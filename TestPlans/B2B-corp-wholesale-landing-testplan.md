дополнительных блоков (FAQ у корп., шаги «как это работает» у опта).

## Разведка (шаг 0, перед написанием тестов) — [OK] пройдено

- **B2B-000** `[OK]`: реальные URL — `/corporate/` (Корпоративным клиентам) и
  `/wholesale/` (Оптовым клиентам), отдельные роуты (не query-параметр). Переключение
  вкладки — полноценная client-side навигация со сменой URL, без «мигания» дефолтной
  вкладки.
- **B2B-001** `[OK]`: реальный эндпоинт отправки формы — `POST .../corporate-leads`
  (тот же эндпоинт используется для обеих вкладок, включая «Оптовым», несмотря на
  название). ⚠️ Важно для будущих автотестов: этот запрос **не всегда виден** через
  `performance.getEntriesByType('resource')` / расширение claude-in-chrome
  (`read_network_requests`) в этой среде — он подтверждён только через реальный
  DevTools пользователя. Не полагаться на пустой список ресурсов как на доказательство
  «запрос не ушёл» — перепроверять другим способом (например `cy.intercept` в реальном
  Cypress-прогоне, а не через это расширение).
- **B2B-002** `[OK]`: весь контент (тексты карточек, ФИО менеджеров, телефоны)
  захардкожен во фронте — во время тестирования не зафиксировано ни одного
  API-запроса, отдающего контент страницы (только `corporate-leads` на сабмит формы
  и трекинг/аналитика). API-проверка контента, соответственно, не требуется — только
  сверка с Figma.

### Форма заявки
- **B2B-050** `[OK]`: пустой сабмит подсвечивает все 5 обязательных полей ошибкой
  «Заполните поле — оно обязательное», не отправляет запрос.
- **B2B-051** `[OK, с оговоркой]`: поле БИН принимает только цифры (буквы отфильтровываются
  маской), лимит 12 цифр. **Важно:** БИН в Казахстане имеет контрольную сумму
  (алгоритм: веса `[1..11]` mod 11, при остатке 10 — веса `[3..11,1,2]` mod 11) —
  форма **тихо** отклоняет сабмит при невалидной чек-сумме, без подсветки поля
  ошибкой. Это не баг форм-валидации как таковой, но UX-риск: пользователь с опечаткой
  в БИН не поймёт, почему форма не отправляется (см. «Открытый вопрос» в BugReport
  README — не заведён как отдельный баг, целью проверки не было).
- **B2B-052** `[OK]`: маска телефона — `+7 XXX XXX-XX-XX`, первый введённый символ
  считается избыточным «7» и не входит в номер (нужно вводить с двойным первым
  символом либо через вставку из буфера) — стандартное поведение маски, не баг.
- **B2B-053** `[OK]`: поле «Город» — свободный текст, без автокомплита.
- **B2B-054**: не проверено отдельно на экстремальные значения (эмодзи/HTML) в этом

- **B2B-055** `[OK]`: успешный сабмит с валидными данными → реальный POST на
