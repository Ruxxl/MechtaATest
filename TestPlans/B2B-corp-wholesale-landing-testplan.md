# План тестов: Лендинг «Корпоративным клиентам» / «Оптовым клиентам»

Источник: Figma, файл Website 2.0
(`https://www.figma.com/design/Hagc86Lw0I2tF7RtH4Hwsr/Website-2.0`).
- Корпоративным клиентам — node `32697:204050`
- Оптовым клиентам — node `32697:204199`

Статус: **план, страница на сайте ещё не реализована, тесты не написаны**.
Черновые ID кейсов: `B2B-xxx` (общее для обеих вкладок), `CORP-xxx` (только
«Корпоративным клиентам»), `OPT-xxx` (только «Оптовым клиентам»).

Обе вкладки — один и тот же шаблон лендинга (сегмент-контрол сверху,
тёмный hero, блоки преимуществ, карточка менеджера, форма заявки, баннер
приложения, футер), различается только контент и состав пары
дополнительных блоков (FAQ у корп., шаги «как это работает» у опта).

⚠️ **Замечание к макету (поднять до реализации):** на вкладке «Оптовым
клиентам» заголовок секции «Прямые поставки без лишних звеньев» используется
дважды подряд — для блока с 3 карточками преимуществ и для блока с 4
пронумерованными шагами процесса. Похоже на copy-paste в макете, второй,
вероятно, должен называться иначе («Как это работает» и т.п.). Если на проде
воспроизведётся как есть — фиксировать отдельным багом (два одинаковых H2 на
странице), не считать штатным.

---

## Разведка (шаг 0, перед написанием тестов)

- **B2B-000**: найти реальный URL/роут страниц (`/b2b/`, `/corporate/`,
  `/wholesale/` — уточнить фактические слаги) и то, как переключение вкладки
  меняет URL (query-параметр, отдельный путь, или чисто клиентский стейт без
  смены URL).
- **B2B-001**: найти реальный эндпоинт отправки формы заявки (POST) —
  перехватить через Network, зафиксировать в тесте точный путь и тело запроса
  вместо предположений (по аналогии с находкой по basket/add — см. память
  проекта: не все POST ловятся `cy.intercept`, для таких ждать смену UI, а не
  сеть).
- **B2B-002**: проверить, приходят ли тексты/номера менеджеров, кейсы карточек
  преимуществ и т.п. с бэкенда (CMS) или захардкожены во фронте — от этого
  зависит, нужен ли API-чек этих полей в принципе.

## Общее для обеих вкладок

### Переключатель вкладок (Segmented Control)
- **B2B-010**: дефолтная вкладка при заходе на `/b2b/`-подобный урл (или что
  открывается по клику на «Корпоративным клиентам» / «Оптовым клиентам» в
  верхней строке хедера/футера — проверить, ведут ли они сразу на нужную
  вкладку).
- **B2B-011**: клик по неактивной вкладке — контент меняется на
  соответствующий (hero-текст, преимущества, форма, менеджер), URL/стейт
  обновляется штатно.
- **B2B-012**: повторный клик по уже активной вкладке — не ломает страницу,
  не сбрасывает введённые в форму данные (если сохраняет то же DOM-дерево, а
  не ремонтирует).
- **B2B-013**: прямой переход по URL сразу на вкладку «Оптовым клиентам»
  (если у неё свой URL) — открывается сразу нужный таб без «мигания»
  дефолтного.
- **B2B-014**: активное состояние вкладки визуально отличается от неактивной
  (не просто по тексту).

### Hero-блок
- **B2B-020**: заголовок/подзаголовок/CTA отображаются полностью, без обрезки
  по тексту на разных ширинах вьюпорта.
- **B2B-021**: кнопка «Оставить заявку» в hero — клик скроллит/переводит
  фокус к форме заявки внизу страницы (в макете это отдельно отрисовано как
  connector-стрелка «Scroll to» — прототипная аннотация, не реальный UI;
  реализацию поведения нужно проверить по факту).
- **B2B-022**: картинка hero не даёт layout shift (зарезервирована высота) и
  не бьёт по CLS.

### Блоки преимуществ (карточки с иконками)
- **B2B-030**: все карточки преимуществ рендерятся с иконкой, заголовком и
  описанием — ни одна не пустая/не битая иконка.
- **B2B-031**: карточки не кликабельны там, где по макету это просто
  инфоблок (нет случайного href/onClick с ошибкой в консоли).

### Карточка менеджера
- **B2B-040**: ФИО, должность и телефон отображаются, телефон — валидный
  формат, кликабелен как `tel:`.
- **B2B-041**: кнопка копирования номера — реально копирует в буфер обмена
  (или email, для вкладки «Оптовым» — см. OPT-041), есть визуальный фидбек
  об успешном копировании.
- **B2B-042**: для «Оптовым клиентам» рядом с телефоном есть email
  `b2b@mechta.kz` с отдельной кнопкой копирования — тоже кликабелен
  (`mailto:`) и копируется.

### Форма заявки
- **B2B-050**: обязательные поля помечены `*` — сабмит с пустой формой
  подсвечивает все обязательные поля ошибкой, не отправляет запрос.
- **B2B-051**: поле «БИН» — валидация формата (РК: 12 цифр), не пропускает
  буквы/меньше-больше цифр; проверить реальное сообщение об ошибке.
- **B2B-052**: поле «Телефон» — маска/валидация казахстанского номера,
  поведение при вставке номера с `+7`/`8`/без кода.
- **B2B-053**: поле «Город» — свободный текст или выпадающий список/автокомплит
  (уточнить по факту реализации), граничные случаи под конкретный тип поля.
- **B2B-054**: поле «Какие товары хотите купить» — лимит длины текста, не
  падает на очень длинном вводе, на эмодзи/HTML-инъекции (аналог найденного
  ранее в ЛК поведения — см. память по BUG-024: РК-профиль тихо дропает
  цифры/HTML, для формы заявки поведение может отличаться, проверить факт, а
  не считать баг заранее).
- **B2B-055**: успешный сабмит — реальный POST на найденный в B2B-001
  эндпоинт с корректным телом, UI показывает подтверждение (тост/модалка/смена
  формы на «спасибо»).
- **B2B-056**: сабмит с ошибкой сети/5xx с бэкенда — форма показывает ошибку
  пользователю, не остаётся в вечном состоянии загрузки, данные полей не
  теряются (можно повторить отправку).
- **B2B-057**: двойной клик/сабмит подряд — не улетает два одинаковых лида
  (дебаунс/дизейбл кнопки на время запроса).
- **B2B-058**: название формы и лейблы полей корректно отличаются между
  вкладками («Оставьте заявку — менеджер свяжется в течение дня» /
  «Получите оптовые условия по вашему региону»; «Название» /
  «Название компании») — при переключении таба не остаётся текст от другой
  вкладки.

### Баннер приложения / Футер
- **B2B-060**: ссылки App Store / Google Play / AppGallery ведут на реальные
  сторы (не заглушки).
- **B2B-061**: QR-код в баннере приложения валиден и ведёт на страницу/диплинк
  скачивания приложения.
- **B2B-062**: в футере пункты «Корпоративным клиентам» / «Оптовым клиентам»
  (в колонке «Партнерам») ведут ровно на соответствующую вкладку этой же
  страницы, а не на общий `/b2b/` без выбранного таба.
- **B2B-063**: подписка на рассылку (поле email в футере) — валидация email,
  успешный/ошибочный сабмит.

### Общие некликовые проверки
- **B2B-070**: responsive — мобильная/планшетная раскладка (сегмент-контрол,
  hero, карточки в колонку, форма в одну колонку вместо двух).
- **B2B-071**: аналитика/трекинг событий — если есть GA/метрика на клик
  «Оставить заявку» и на сабмит формы, события уходят с корректными
  параметрами (uncheck, если трекинг не задействован на этой странице).
- **B2B-072**: SEO — заголовок вкладки/meta, хлебные крошки (если есть),
  корректно меняются при переключении таба.

## Только «Корпоративным клиентам»

- **CORP-001**: секция «Весь ассортимент» — 2 карточки («Для любой отрасли»,
  «Нужного товара нет в наличии?») отображаются с текстом без обрезки.
- **CORP-002**: FAQ-аккордеон — клик по вопросу разворачивает ответ, повторный
  клик сворачивает; открыт максимум один пункт одновременно (или несколько —
  зафиксировать фактическое поведение).
- **CORP-003**: FAQ — состояние (открыт/закрыт пункт) не ломается при
  ресайзе/смене вкладки на «Оптовым» и обратно.
- **CORP-004**: содержимое ответов FAQ («Как оформить покупку на юр. лицо» и
  т.д.) не пустое и не содержит плейсхолдерный текст.

## Только «Оптовым клиентам»

- **OPT-001**: секция «Прямые поставки без лишних звеньев» (первая, с 3
  карточками) — Весь ассортимент / Самовывоз с центральных складов /
  Резервирование под вашу заявку — отображаются корректно.
- **OPT-002**: отдельная широкая карточка «Предзаказы со стоков поставщика» —
  не путается по сетке с карточками из OPT-001 на разных ширинах.
- **OPT-003**: блок «Как это работает» (4 шага, пронумерованы 1-2-3-4) —
  порядок шагов не переставляется, номера соответствуют тексту (см.
  предупреждение про дублирующийся заголовок секции в шапке файла).
- **OPT-004**: степпер шагов не кликабелен/не должен вести никуда — если в
  реализации на шаги повесят ссылки, это уже отклонение от макета.

## Кросс-табличные кейсы

- **X-001**: заполнить форму на вкладке «Корпоративным», переключиться на
  «Оптовым» и обратно — проверить, сохраняются ли введённые данные (ожидаемо
  нет, так как поля/лейблы разные, но сам факт — зафиксировать).
- **X-002**: открыть в двух вкладках браузера разные табы страницы
  (корп/опт) — независимая работа форм, не путаются эндпоинты/менеджеры при
  сабмите.
