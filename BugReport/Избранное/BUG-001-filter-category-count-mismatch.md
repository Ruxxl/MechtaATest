# BUG-001: Счётчики категорий в фильтре «Избранное» не совпадают с реальным количеством товаров

**Раздел:** Избранное (`/favorites/`, `GET /api/v3/favorites/filter` vs `GET /api/v3/favorites`)
**Severity:** Low
**Приоритет:** Low
**Статус:** Подтверждён
**Дата:** 2026-08-19
**Окружение:** `https://pp.yc.mechta.kz/`, API `https://www.mechta.kz/api/v3`

## Предусловия

Авторизованный пользователь, в избранном реально 3 товара: 1 ноутбук («ПК, ноутбуки,
периферия») и 2 кондиционера («Техника для дома»).

## Шаги воспроизведения

1. Открыть `/favorites/`.
2. Сравнить заголовок страницы («N товаров») с числом в сайдбар-фильтре «Категории →
   Все».

Дополнительно воспроизведено через прямые API-запросы:

```bash
# Реальный список — totalCount корректный
curl -s "https://www.mechta.kz/api/v3/favorites" \
  -H "X-City-Code: astana" -H "X-Mechta-Device-Id: <id>" -b cookies.txt | jq '.meta, (.products | map(.name))'

# Счётчики фильтра — расходятся с реальным списком
curl -s "https://www.mechta.kz/api/v3/favorites/filter" \
  -H "X-City-Code: astana" -H "X-Mechta-Device-Id: <id>" -b cookies.txt | jq
```

## Ожидаемый результат

Число в заголовке страницы, сумма счётчиков категорий в фильтре и общий счётчик «Все»
должны совпадать друг с другом и с реальным количеством товаров в избранном.

## Фактический результат

- Заголовок страницы: «Избранное **3 товара**» — совпадает с реальным списком.
- `GET /api/v3/favorites` → `meta.totalCount: 3`, `products` содержит 3 позиции (1
  ноутбук + 2 кондиционера).
- `GET /api/v3/favorites/filter` → `presence.exist: 4`, категории:
  ```json
  {"categories":[
    {"slug":"noutbuki-i-kompyutery","name":"ПК, ноутбуки, периферия","productCount":2},
    {"slug":"tehnika-dlya-doma","name":"Техника для дома","productCount":2}
  ],"presence":{"exist":4,"not_exist":0}}
  ```
  Категория «ПК, ноутбуки, периферия» показывает **2**, хотя в избранном реально только
  **1** ноутбук — сайдбар-фильтр отображает «Все 4» вместо реальных 3.

Товар/категория, из-за которой возникает лишняя единица, не идентифицирован явно (в
основном списке избранного `/api/v3/favorites` товар с таким доп. количеством не
возвращается вовсе) — похоже на связанный с этим эндпоинтом отдельный товар (возможно
более недоступный/архивный), который `/filter` всё ещё учитывает, а основной список уже
корректно исключает.

## Скриншоты

`screenshots/bug001-favorites-filter-count-mismatch.jpg` — страница «Избранное»: заголовок
«3 товара», сайдбар «Все 4» / «ПК, ноутбуки, периферия 2» / «Техника для дома 2».

## Вероятная причина

`/api/v3/favorites/filter` (эндпоинт для счётчиков категорий/фасетов) и
`/api/v3/favorites` (эндпоинт самого списка) расходятся в бизнес-логике фильтрации —
похоже, `/filter` не применяет ту же фильтрацию по доступности/актуальности товара, что
и основной список, и продолжает учитывать в подсчёте категорию для товара, который уже
исключён из выдачи самого списка.

## Автотест, фиксирующий баг

Автотеста нет — найдено при живом сквозном регресс-тестировании функционала
`pp.yc.mechta.kz` 2026-08-19.
