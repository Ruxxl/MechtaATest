# BUG-006: personal_info.full_name в заказах — с ведущим пробелом и в обратном порядке (Фамилия Имя вместо Имя Фамилия)

**Раздел:** Личный кабинет — Мои заказы, API `GET /v2/personal/orders_list`
**Severity:** Low
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-06
**Окружение:** `http://api.d.im.mdev.kz/v2/personal/orders_list` (тестовый стенд d2)

## Предусловия

Авторизованный пользователь с именем «Джон» и фамилией «Appleseed»
(подтверждено в `GET /v2/personal` → `data.profile_info.full_name: "Джон
Appleseed"`).

## Шаги воспроизведения

1. `GET http://api.d.im.mdev.kz/v2/personal/orders_list?status=active&page=1&limit=10`.
2. Взять поле `order.personal_info.full_name` у ЛЮБОГО заказа в ответе.
3. Сравнить с `data.profile_info.full_name` из `GET /v2/personal`.

## Ожидаемый результат

`personal_info.full_name` заказа должен совпадать по формату и порядку слов
с `profile_info.full_name` профиля — «Джон Appleseed» (Имя Фамилия), без
лишних пробелов.

## Фактический результат

`personal_info.full_name` у **всех без исключения** заказов на первой
странице (10 из 10 проверенных) равно ровно `" Appleseed John"` —
с ведущим пробелом И в обратном порядке слов (Фамилия Имя вместо Имя
Фамилия), при этом это одно и то же значение для каждого заказа независимо
от даты/типа заказа (константа, не персональные данные конкретного заказа).

## Скриншоты

Баг воспроизведён на уровне API-ответа, не рендерится напрямую как видимый
текст в списке заказов (в списке отображается только номер/сумма/статус, ФИО
получателя в списке не показывается) — визуальное подтверждение потребуется
на странице детализации заказа, если там это поле используется.

## Вероятная причина

Похоже на конкатенацию `last_name + ' ' + first_name` без `trim()` вместо
`first_name + ' ' + last_name` — типичная ошибка сборки строки ФИО на
бэкенде (в отличие от `/v2/personal`, где та же пара имя/фамилия собрана
верно и без пробела). Раз в двух разных эндпоинтах для одного и того же
пользователя порядок конкатенации разный — это рассинхрон между
бэкенд-сервисами (см. правило проекта: расхождение данных между эндпоинтами
считается багом).

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/cabinet/orders.cy.js` — тест сверяет
`personal_info.full_name` заказа с `profile_info.full_name` профиля и падает,
пока расхождение не исправлено.
