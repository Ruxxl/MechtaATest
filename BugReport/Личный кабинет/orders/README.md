# Баги, найденные при тестировании раздела «Мои заказы» (/cabinet/orders/)

Дата: 2026-08-06
Стенд: `http://d2.im.mdev.kz/` (тестовый), API `http://api.d.im.mdev.kz`

| ID | Название | Severity | Статус |
|---|---|---|---|
| [BUG-004](./BUG-004-zero-price-orders-with-real-payment.md) | Заказы с непустым `payment_info.to_pay` показывают «0 ₸» в списке (фронт берёт `basket.total_prices` вместо `payment_info`) | High | Подтверждён |
| [BUG-005](./BUG-005-orders-count-arithmetic-mismatch.md) | `orders_count.active + cancelled + finished` ≠ `orders_count.all` (расхождение стабильно ≈ значению `cancelled`) | Medium | Подтверждён |
| [BUG-007](./BUG-007-created-at-timezone-offset.md) | `created_at` заказа систематически на 5 часов отстаёт от `statuses[].date` того же события (UTC vs UTC+5) | Medium | Подтверждён |
| [BUG-008](./BUG-008-missing-page-title.md) | На странице «Мои заказы» нет `<h1>`/заголовка страницы вообще | Low | Подтверждён |
| [BUG-009](./BUG-009-payment-failed-banner-not-shown-for-some-orders.md) | Карточка рендерит `summary.title.text`, а не `order_status_banner.title` — у 3 из 4 заказов с ошибкой оплаты предупреждение вообще не показывается | High | Подтверждён |

Нумерация продолжает `../cabinet_overview/` (BUG-001..003) — единая
последовательность в рамках раздела «Личный кабинет».

## Что НЕ было оформлено как баг (и почему)

- **`personal_info.full_name` заказа = `" Фамилия Имя"`** (ведущий пробел,
  обратный порядок слов), расходится с `profile_info.full_name` из
  `/v2/personal`. Изначально заведён как BUG-006, отклонён заказчиком
  2026-08-07 как ожидаемое поведение этого поля — файл и тест удалены.
- **Одинаковый текст причины отмены на всех отменённых заказах**
  (`order_status_banner.description.message: "Причина: Покупатель отменил
  заказ по просьбе продавца"` — идентично на всех 10 проверенных отменённых
  заказах). Подозрительно похоже на плейсхолдер, а не персональную причину
  каждой отмены, но это контентный/копирайтерский вопрос, а не явное
  нарушение контракта API или поломка фронта — нужно уточнение у
  аналитика/бэкенда, помечено как открытый вопрос, не баг.
- **Запрос «Ещё заказы» (page>1) не передаёт параметр `limit` вовсе** — только
  самый первый запрос (page=1) содержит `limit=10`. Расходится с TC-МО-33
  («limit всегда фиксирован»), но не ломает отображение — сервер, видимо,
  применяет тот же лимит по умолчанию без явного параметра. Не подтверждён
  как баг без уточнения у бэкенда, зафиксировано как факт поведения.
- **Прямой заход на `/cabinet/orders/` без авторизации** показывает отдельную
  страницу `/cabinet/unauthorized/` с текстом «Войдите или зарегистрируйтесь»
  (а не модалку поверх главной, как для `/cabinet/`) — это осмысленный
  отдельный UX-паттерн для вложенных страниц ЛК, не баг, но стоит держать в
  уме при написании тестов на разные страницы раздела (поведение НЕ
  одинаковое для `/cabinet/` и `/cabinet/orders/`).
