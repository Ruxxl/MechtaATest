# BUG-004: Заказы с реальной суммой к оплате (payment_info.to_pay) показывают «0 ₸» в списке «Мои заказы»

**Раздел:** Личный кабинет — Мои заказы (`/cabinet/orders/`), карточка заказа
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-06
**Окружение:** `http://d2.im.mdev.kz/cabinet/orders/` (тестовый стенд d2)

## Предусловия

У пользователя есть заказы, где `basket.items` пуст (`[]`) — судя по всему,
это заказы с цифровыми товарами/ключами активации, оформленными через иной
механизм, чем обычная корзина. У таких заказов `payment_info.to_pay` и
`payment_info.total` при этом ненулевые (заказ реально стоит денег и по нему
даже есть платёж в `payment_info.payments[]`).

## Шаги воспроизведения

1. Авторизоваться, открыть `/cabinet/orders/`, вкладка «Активные».
2. Найти карточку заказа с заголовком «Ключ активации будет доступен в
   течение 15 минут» (напр. № 4350, № 4348, № 4347).
3. Сравнить сумму, отображаемую в правом верхнем углу карточки, с
   `payment_info.to_pay` / `payment_info.total` этого же заказа в ответе
   `GET /v2/personal/orders_list?status=active&page=1&limit=10`.

## Ожидаемый результат

Сумма на карточке заказа соответствует реальной сумме к оплате из
`payment_info.to_pay` (или `total`) — например, для заказа № 4350 это
**1 275 518 ₸**, для № 4348 — **1 485 ₸**, для № 4347 — **1 252 192 ₸**.

## Фактический результат

Все три заказа (№ 4350, № 4348, № 4347) отображают **«0 ₸»** — притом что по
данным API это заказы на суммы от полутора тысяч до более чем миллиона тенге
с реально проведённым платежом (`payment_info.payments[0].is_paid: true`).
Заказ № 4346 (со статусом «Оплата не прошла, деньги не списались») тоже
показывает «0 ₸», хотя его `payment_info.to_pay` не равен нулю.

Сверка по API:

| Заказ | UI показывает | `payment_info.to_pay` | `basket.items.length` | `basket.total_prices.discounted_price` |
|---|---|---|---|---|
| № 4350 | 0 ₸ | 1 275 518 | 0 | 0 |
| № 4348 | 0 ₸ | 1 485 | 0 | 0 |
| № 4347 | 0 ₸ | 1 252 192 | 0 | 0 |
| № 22000 (для сравнения) | 6 990 ₸ | 6 990 | 1 | 6 990 |

Закономерность однозначная: сумма на карточке совпадает не с
`payment_info.to_pay`/`total`, а с `basket.total_prices.discounted_price` —
а он равен 0 всякий раз, когда `basket.items` пуст (что, видимо, характерно
именно для этого типа «ключ активации»-заказов, оформленных не через
стандартную корзину). То есть фронт использует **не то поле** для отображения
итоговой суммы заказа в списке.

## Вероятная причина

Карточка заказа в списке берёт сумму из `basket.total_prices.discounted_price`
(рассчитывается на основе состава `basket.items`), а не из
`payment_info.to_pay`/`total` (реальная сумма к оплате/оплаченная сумма).
Для заказов, оформленных без обычной корзины (`basket.items: []`), это даёт
явно неверный «0 ₸» вместо реальной стоимости заказа — серьёзно вводит
пользователя в заблуждение относительно того, сколько денег он потратил.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/cabinet/orders.cy.js` — тест сверяет сумму на
карточке заказа с `payment_info.to_pay` для заказа с пустым `basket.items`
и падает, пока баг не исправлен.
