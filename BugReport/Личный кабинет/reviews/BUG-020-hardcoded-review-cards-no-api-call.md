# BUG-020 [P1/КРИТИЧНО]: ВСЯ страница «Отзывы» (обе вкладки) показывает захардкоженные данные — ни один реальный API-запрос не отправляется

**Раздел:** Личный кабинет — Отзывы (`/cabinet/reviews/`), вкладка «Оставить отзыв»
**Severity:** Critical
**Приоритет:** Critical
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/reviews/` (тестовый стенд d2), API `http://api.d.im.mdev.kz`

## Предусловия

Пользователь авторизован, реальный ответ
`GET http://api.d.im.mdev.kz/v2/reviews/waiting-products` для этого
аккаунта — `{result: true, errors: [], data: {banner: null, products:
null}}` (подтверждено прямым запросом непосредственно перед и во время
теста).

## Шаги воспроизведения

1. Залогиниться тестовым аккаунтом (0000000000/0000).
2. Открыть `/cabinet/reviews/` (или перейти на вкладку «Оставить отзыв»,
   которая открыта по умолчанию).
3. Открыть DevTools → Network, отфильтровать по `api.d.im.mdev.kz`.
4. Выполнить `location.reload(true)` (жёсткая перезагрузка, без кэша).
5. Сравнить список реально отправленных сетевых запросов с содержимым,
   отображаемым на экране.

## Ожидаемый результат

Блок «Оставить отзыв» должен отражать РЕАЛЬНЫЕ данные из
`GET /v2/reviews/waiting-products` для авторизованного пользователя. Раз
API возвращает `products: null` и `banner: null` — блок должен быть либо
скрыт полностью, либо показывать пустое состояние («Нет товаров для
отзыва»), но не показывать несуществующие товары.

## Фактический результат

На экране отображается баннер **«Оцените товары и заработайте до 6 000
бонусов»** и **3 идентичные карточки** «Смарт-часы Huawei Watch GT 5 Pro
Titanium (55020DGG)», каждая — «Осталось 2 месяца для обзора», «+1 500 Б»,
со звёздным рейтингом для оценки.

При этом за весь цикл загрузки страницы (включая жёсткую перезагрузку без
кэша) **запрос `GET /v2/reviews/waiting-products` не отправляется вообще**
— в списке реальных сетевых запросов к `api.d.im.mdev.kz` этого эндпоинта
нет (проверено дважды: обычная навигация и `location.reload(true)`).
Единственный релевантный запрос к разделу отзывов —
`GET /v2/reviews/personal?filter=all&page=0` (для вкладки «Мои отзывы», не
для «Оставить отзыв»).

Это означает: содержимое вкладки «Оставить отзыв» (баннер + 3 карточки)
**не приходит с бэкенда пользователя вообще** — оно либо захардкожено на
фронте, либо взято из какого-то иного, не относящегося к текущему
пользователю источника (напр. общий демо-фикстур, оставшийся после
разработки/тестирования и не убранный из продакшен-сборки для этого
стенда). Товар «Смарт-часы Huawei Watch GT 5 Pro Titanium» никак не связан
с реальными покупками тестового аккаунта (среди его заказов на листах
«Мои заказы»/«Бонусы и фишки» такого товара нет).

Дополнительно (см. также TC-ОТ-8/ТС-ОТ-9 из тест-плана, которые
предвосхищали эту находку): 3 карточки суммарно дают 1500×3=4500 Б, а
баннер утверждает «до 6 000 бонусов» — расхождение подтверждает, что оба
числа (карточки и баннер) взяты из разных мест и не пересчитываются
согласованно, что дополнительно подтверждает отсутствие реальной связи с
живыми данными.

**Обновление (та же сессия, углублённая проверка): вкладка «Мои отзывы»
страдает от ТОЙ ЖЕ проблемы.** Переключение на вкладку «Мои отзывы»
кликом **не отправляет ни одного запроса** к `api.d.im.mdev.kz`
(проверено через мониторинг сети во время клика — ноль запросов), при
этом на экране появляются **3 идентичные карточки «опубликованного»
отзыва** на тот же товар «Смарт-часы Huawei Watch GT 5 Pro Titanium»,
каждая — 5 звёзд, дата «13 апреля», «Начислено 1000 Б». Повторный прямой
запрос `GET /v2/reviews/personal?filter=all&page=0` в этот же момент
подтверждает: `data.reviews: null`, `data.meta: null` — по данным API у
пользователя вообще НЕТ отзывов. Также в шапке при переключении на эту
вкладку появляется ЕЩЁ одно число, отсутствовавшее на вкладке «Оставить
отзыв» — «300 Бонусов» (см. также BUG-022 про источник блока статистики).

Итого: **обе вкладки страницы «Отзывы» показывают полностью
захардкоженный/демо-контент**, не имеющий отношения к реальному состоянию
аккаунта — это не баг одного виджета, а системная проблема всей страницы.

## Уточнение (повторная проверка через автотест Cypress, чистая сессия)

В полностью свежей сессии (Cypress, без долгоживущей вкладки браузера с
историей SPA-навигации) запрос `GET /v2/reviews/waiting-products`
**реально отправляется** при заходе на вкладку «Оставить отзыв» —
перехвачен через `cy.intercept()`, подтверждён. НО итог тот же: даже
получив в ответ `products: null`, интерфейс **всё равно показывает** те же
3 захардкоженные карточки «Смарт-часы Huawei Watch GT 5 Pro Titanium».

Это уточняет диагноз: проблема не (только) в отсутствии сетевого запроса
(в моей исходной ручной проверке через долгоживущую вкладку браузера
запрос действительно не отправлялся при SPA-навигации — возможно,
из-за кэширования состояния на клиенте между переходами), а в том, что
**даже получив корректный пустой ответ от API, фронт игнорирует его и
рендерит статичный fallback-контент вместо пустого состояния**. Оба
пути (без запроса вовсе — при SPA-переходе; с запросом, но с
игнорированием ответа — при прямой загрузке) сходятся в одном и том же
пользователь-видимом дефекте: несуществующие данные показываются как
реальные.

## Вероятная причина

Компонент вкладки «Оставить отзыв», похоже, использует
захардкоженные/дефолтные карточки-заглушки в качестве fallback при пустом
ответе API, вместо того чтобы показывать пустое состояние — заглушка,
задуманная как «пример для дизайна», осталась активной в проде вместо
условного рендера, зависящего от реального `products === null`.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/cabinet/reviews.cy.js` — тест перехватывает
`GET /v2/reviews/waiting-products` и проверяет, что он РЕАЛЬНО
отправляется при открытии вкладки «Оставить отзыв», и что содержимое
экрана соответствует его ответу; падает, пока баг не исправлен.
