# BUG-022: Блок статистики «60 Отзывов | 0 Лайков | 0 Просмотров» не может быть построен из ответа GET /v2/reviews/personal

**Раздел:** Личный кабинет — Отзывы (`/cabinet/reviews/`)
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён (источник данных не определён — вероятно тот же корень, что и BUG-020)
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/reviews/` (тестовый стенд d2), API `http://api.d.im.mdev.kz`

## Предусловия

Пользователь авторизован. `GET /v2/reviews/personal?filter=all&page=0`
возвращает `data.meta: null`, `data.reviews: null`, все `filters[].count`
равны `0`.

## Шаги воспроизведения

1. Открыть `/cabinet/reviews/`.
2. Проверить блок статистики под заголовком «Отзывы» — «N Отзывов | N
   Лайков | N Просмотров».
3. Сверить показанные числа с ответом `GET /v2/reviews/personal?filter=all&page=0`
   и любых других запросов, реально уходящих со страницы.

## Ожидаемый результат

Числа в блоке статистики должны браться из реального ответа API,
соответствующего фактическому количеству отзывов/лайков/просмотров этого
пользователя.

## Фактический результат

На экране показано **«60 Отзывов | 0 Лайков | 0 Просмотров»**. При этом
`GET /v2/reviews/personal?filter=all&page=0` — единственный релевантный
запрос, реально уходящий со страницы (см. BUG-020) — не содержит НИ ОДНОГО
поля, из которого можно было бы получить «60»: `meta: null`, все
`filters[].count: 0` (включая `filters[0].code: "all"`, `count: 0`).

Число «60» не соответствует ни одному известному полю ни в этом, ни в
других проверенных ранее API этого аккаунта. Учитывая уже подтверждённый
BUG-020 (вкладка «Оставить отзыв» показывает полностью захардкоженный
контент без единого реального API-запроса), весьма вероятно, что блок
статистики страдает от того же корня — цифры «60/0/0» тоже
захардкожены/взяты из демо-данных, а не вычислены для текущего
пользователя.

## Скриншоты

См. `../reviews/screenshots/bug020-hardcoded-review-cards.png` — на нём же
виден блок «60 Отзывов | 0 Лайков | 0 Просмотров» в самом верху.

## Вероятная причина

Тот же корень, что и BUG-020 — либо этот блок статистики тоже
захардкожен/берёт данные из статичного мока, либо использует эндпоинт, не
зафиксированный ни в тест-плане, ни в проверенных сетевых запросах (в этом
случае нужно попросить разработчиков указать реальный источник).

## Автотест, фиксирующий баг

`cypress/e2e/main_test/cabinet/reviews.cy.js` — тест сверяет число
отзывов в блоке статистики с данными из `GET /v2/reviews/personal` и
падает, пока источник не будет исправлен/задокументирован.
