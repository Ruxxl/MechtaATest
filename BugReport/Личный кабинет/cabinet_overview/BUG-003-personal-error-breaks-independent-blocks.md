# BUG-003: Ошибка GET /v2/personal обрушивает ВСЮ правую колонку ЛК, включая полностью независимые от неё блоки

**Раздел:** Личный кабинет — обзорная страница `/cabinet/`, обработка ошибок API
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-06
**Окружение:** `http://d2.im.mdev.kz/cabinet/` (тестовый стенд d2), API `http://api.d.im.mdev.kz`

## Предусловия

Пользователь авторизован, `GET http://api.d.im.mdev.kz/v2/personal` отвечает
ошибкой (проверено на 500 Internal Server Error; воспроизводится также с
`200 OK` и `result: false` в теле).

## Шаги воспроизведения

1. Авторизоваться.
2. Перехватить/смоделировать ошибку ответа `GET /v2/personal` (500 или
   `result: false`).
3. Открыть `/cabinet/`.
4. Подождать несколько секунд после ответа API.
5. Сравнить с обычной загрузкой страницы (без ошибки).

## Ожидаемый результат

Блок профиля (ФИО/телефон/баланс), который РЕАЛЬНО зависит от `/v2/personal`,
корректно показывает состояние ошибки (или хотя бы не зависает в skeleton
навечно). Остальные блоки страницы, которые НЕ зависят от этого эндпоинта,
должны продолжать отображаться в штатном режиме:

- Заголовок `h1` «Личный кабинет» — статичный текст, не требует API вообще.
- Блок «Мечта ГИД» — полностью статичный контент («Раздел с ответами и
  полезной информацией» + кнопка), без какой-либо зависимости от API.
- «Моё избранное» / «Оставьте отзыв» — зависят от других эндпоинтов
  (избранное, `/v2/reviews/waiting-products`), не от `/v2/personal`.
- «Вы недавно смотрели» — зависит от `/v3/personal/history`, отдельного
  эндпоинта, не от `/v2/personal`.

Именно так описывает ожидаемое поведение сам тест-план (TC-ЛИ-77, TC-ЛИ-79):
«остальные независимые блоки (Мечта ГИД и т.п.) продолжают отображаться».

## Фактический результат

Вся правая колонка страницы (весь `<main>` контент правее блока профиля)
становится полностью пустой — ни заголовка `h1`, ни «Моё избранное», ни
«Оставьте отзыв», ни «Мечта ГИД», ни карусели «Вы недавно смотрели». Пустая
белая область на месте всего этого контента, бессрочно (не skeleton, а
буквально ничего). Сам блок профиля слева зависает в skeleton-состоянии
(серые плашки-плейсхолдеры вместо ФИО/телефона) без перехода в состояние
ошибки — то есть отдельно фиксируется ещё и TC-ЛИ-88 (skeleton не должен
зависать бессрочно при ошибке API).

Баланс («Ваш баланс» → 0 бонусов / 0 фишек) при этом **отображается**, хотя
эти значения тоже приходят из того же `/v2/personal` — что указывает на
рассинхрон: часть данных из ответа рендерится с дефолтным fallback (0), а
часть (ФИО/телефон) остаётся в вечном skeleton, а остальная страница вовсе
не рендерится.

Воспроизведено дважды независимо (500 и result:false), поведение идентичное.

## Вероятная причина

Похоже, что все секции правой колонки страницы `/cabinet/` (включая
статичный блок «Мечта ГИД» и независимые от `/v2/personal` виджеты)
объединены на уровне компонента одним общим условием рендера — например,
`v-if`/условный рендер, завязанный на успешный ответ ОДНОГО общего
родительского запроса `/v2/personal`, вместо того чтобы каждый блок сам
управлял своим состоянием загрузки/ошибки независимо. Ошибка в одном
эндпоинте валит целиком весь блок вместо изолированной деградации только
тех виджетов, что реально от него зависят.

`cypress/e2e/Regress_Test/cabinet/cabinet_overview.cy.js` — тесты
