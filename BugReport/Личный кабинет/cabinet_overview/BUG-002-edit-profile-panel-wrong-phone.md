# BUG-002: В панели «Редактировать данные» поле «Телефон» показывает не тот номер, что реально привязан к аккаунту

**Раздел:** Личный кабинет — Блок профиля, панель редактирования данных (страница `/cabinet/`)
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-06
**Окружение:** `http://d2.im.mdev.kz/cabinet/` (тестовый стенд d2)

## Предусловия

Пользователь авторизован под тестовым аккаунтом с телефоном `0000000000`
(отображается в шапке ЛК как «+7 (000) 000-0000»).

## Шаги воспроизведения

1. Открыть `/cabinet/`.
2. Кликнуть на блок ФИО/телефон слева (или на стрелку `>` рядом с именем) —
   открывается модалка «Редактировать данные».
3. Проверить значение поля «Введите телефон» в блоке «Контакты».
4. Сравнить с реальным номером аккаунта, показанным в шапке ЛК и в ответах
   API (`/v2/personal`, `/v2/user`).

## Ожидаемый результат

Поле «Телефон» в панели редактирования должно быть предзаполнено реальным
телефоном аккаунта — `0000000000` (в UI-формате `+7 (000) 000-0000`), без
искажений, как того явно требует тест-кейс TC-ЛИ-8 («Данные в панели
редактирования профиля предзаполнены корректно»).

## Фактический результат

Поле показывает `+7 700 000-00-00` — номер, не совпадающий ни с одним полем
в ответах API этого аккаунта:

- `GET /v2/personal` → `data.profile_info.phone: "0000000000"`
- `GET /v2/user` → `data.phone: "0000000000"`

Ни в одном из проверенных ответов бэкенда нет значения `700 000 00 00` или
чего-либо похожего — это подтверждено через `fetch()` в консоли на этой же
странице сразу после открытия панели. Поле физически задизейблено
(`disabled`), то есть пользователь не может его отредактировать и случайно
сохранить неверное значение, но сам факт показа **другого** номера вместо
настоящего вводит пользователя в заблуждение относительно того, какой номер
привязан к его аккаунту.

Значение `+7 700 000-00-00` похоже на типовой демо-шаблон номера (популярный
казахстанский префикс 700), что указывает на вероятную причину — см. ниже.

## Вероятная причина

Поле `contact_phone` в разметке (`<input name="contact_phone" disabled
value="+7 700 000-00-00">`) не привязано к реальному значению
`profile_info.phone` / `data.phone` из API, а получает статичное/дефолтное
значение — похоже на захардкоженный пример маски телефона (`+7 700
000-00-00` — типичный шаблон для казахстанского номера), который
разработчик не заменил на реальный биндинг к данным пользователя, либо
маска компонента применяется к неверному источнику данных (полю,
отличному от `profile_info.phone`) и в случае с тестовым номером
`0000000000` (не проходящим валидацию маски как реальный номер) откатывается
на дефолт.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/cabinet/cabinet_overview.cy.js` — тест
«Данные в панели редактирования профиля предзаполнены корректно» сверяет
значение поля «Телефон» в панели с `data.profile_info.phone` из
`GET /v2/personal` и падает, пока баг не исправлен.
