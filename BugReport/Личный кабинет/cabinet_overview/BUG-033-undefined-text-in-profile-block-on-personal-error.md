# BUG-033: При ошибке `GET /v2/personal` в блоке профиля (сайдбар `/cabinet/`) виден буквальный текст «undefined» вместо имени/телефона

**Раздел:** Личный кабинет — обзорная страница `/cabinet/`, блок профиля (сайдбар)
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата:** 2026-08-10
**Окружение:** `http://d2.im.mdev.kz/cabinet/` (тестовый стенд d2)

## Предусловия

Пользователь авторизован, `GET http://api.d.im.mdev.kz/v2/personal` отвечает
ошибкой — воспроизведено при ДВУХ разных видах ошибки:
1. `200 OK` с телом `{result: false, errors: [...], data: null}`.
2. Обычный `500 Internal Server Error` (пустое тело).

Это отдельная, более узкая находка, обнаруженная при повторной проверке уже
закрытого [BUG-003](../orders/README.md) (та же строка воспроизведения, тот
же эндпоинт) — BUG-003 был про полное исчезновение ВСЕЙ правой колонки
целиком, это исправлено и подтверждено. Данный баг — про остаточный
артефакт именно в левом блоке профиля, который BUG-003 не описывал.

## Шаги воспроизведения

1. Авторизоваться, перехватить/подменить ответ `GET /v2/personal` (любым из
   двух способов выше — через `window.fetch` override или `cy.intercept`).
2. Открыть/перейти на `/cabinet/` (SPA-переход, без полной перезагрузки).
3. Посмотреть на блок профиля в левом сайдбаре, вторую строку под именем
   (там, где обычно телефон).

## Ожидаемый результат

При ошибке загрузки профиля вторая строка блока (телефон) должна показывать
либо ничего, либо skeleton-заглушку, либо содержательное сообщение об
ошибке — не буквальный текст JS-примитива.

## Фактический результат

Живьём подтверждено (скриншот прилагается): в строке под аватаром/именем
буквально отображается серым текстом **«undefined»**. Это не скрытый через
CSS элемент — `getBoundingClientRect().width > 0`, `display !== 'none'`,
элемент реально виден пользователю. DOM: `<p class="text-mi-body-1
text-mi-text-secondary lg:mt-0.5">undefined</p>`.

Судя по всему, компонент пытается вывести `profile_info.phone` (или
аналогичное поле), а при `data: null`/ошибке получает JS `undefined` и
скармливает его напрямую в текстовый интерполятор без проверки/fallback —
классическая ошибка отсутствия guard-условия при рендере производного от
API поля.

## Вероятная причина

Тот же компонент блока профиля, что чинили при исправлении BUG-003
(теперь остальная колонка независимо рендерится), но конкретно в самом
блоке профиля осталась непроверенная интерполяция поля телефона —
`{{ profile_info?.phone }}` без `?? ''`/условного рендера, или аналог.

## Автотест, фиксирующий баг

`cypress/e2e/main_test/cabinet/cabinet_overview.cy.js` — тест
«GET /v2/personal с result:false не крашит страницу» (уже существовал для
BUG-003) сверяет отсутствие текста «undefined» в `<main>` и падает на этом
конкретном артефакте, хотя основная часть BUG-003 (правая колонка) уже
исправлена. Тест на голую 500-ошибку («таймаут/500 не роняет всю
страницу») пока НЕ проверяет это конкретно — стоит расширить и его тем же
assert’ом.
