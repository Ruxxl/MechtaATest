# BUG-025: Карточка ФИО (сайдбар + шапка сайта) не обновляется после сохранения профиля без перезагрузки страницы

**Раздел:** Личный кабинет — Редактирование профиля (модалка «Редактировать данные», `/cabinet/`)
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/` (тестовый стенд d2)

## Предусловия

Пользователь авторизован, находится на `/cabinet/`.

## Шаги воспроизведения

1. Кликнуть на блок ФИО в сайдбаре — открывается модалка «Редактировать
   данные».
2. Изменить «Имя» на новое значение (например, `Пётр`), нажать «Сохранить».
3. Дождаться тоста «Успешно» (сохранение подтверждено, поля модалки
   действительно показывают новое значение — сама модалка обновляется
   корректно).
4. Закрыть модалку крестиком (без перезагрузки страницы).
5. Посмотреть на карточку ФИО в сайдбаре `/cabinet/` (слева) и на имя в
   шапке сайта (справа сверху, рядом с иконкой профиля).

## Ожидаемый результат

Оба места сразу показывают новое значение — «Пётр Appleseed» в карточке
слева и «Пётр» в шапке справа, без необходимости обновлять страницу
(тест-план — TC-080, TC-082).

## Фактический результат

И карточка в сайдбаре, и имя в шапке сайта продолжают показывать СТАРОЕ
значение («Джон Appleseed» / «Джон») — при том что сохранение по факту
прошло успешно (подтверждено прямым запросом `GET /v3/profile`: бэкенд уже
вернул `firstname: "Пётр"`). Несоответствие сохраняется даже после закрытия
модалки — обновление происходит ТОЛЬКО после полной перезагрузки страницы
(F5 или повторный `cy.visit`), после чего обе точки отображения корректно
показывают «Пётр».

## Вероятная причина

Сама модалка обновляет своё внутреннее состояние собственным повторным
`GET /v3/profile` после успешного сохранения (см. разведку сети в
`project_lk_testing_d2_stand` memory), но родительские компоненты страницы
(карточка сайдбара `/cabinet/` и шапка сайта) не подписаны на этот же
источник данных / не получают события об обновлении профиля — у них,
судя по всему, отдельное, никак не инвалидируемое состояние, которое
обновляется только при новой загрузке страницы.

## Автотест, фиксирующий баг

`cypress/e2e/main_test/cabinet/edit_profile.cy.js`, describe-блок
«Редактирование профиля — синхронизация после сохранения (TC-080..083)» —
тесты ожидают немедленное обновление `h2` карточки без reload и падают,
пока баг не исправлен. Отдельно подтверждено, что часть после `cy.reload()`
(TC-081 — персистентность на бэкенде) работает корректно — баг именно в
отсутствии живого обновления UI, а не в потере данных.
