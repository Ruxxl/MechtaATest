## Исправленные баги (файлы удалены)

- **BUG-025** («Карточка ФИО в сайдбаре и имя в шапке сайта не
  обновляются сразу после сохранения профиля — только после F5», Jira
  AS-4530) — исправлен, подтверждено 2026-08-10: карточка теперь
  обновляется без перезагрузки страницы, с задержкой ~1-2 сек после
  сохранения (подтверждено автотестом — `cy.should` с retry ловит
  обновлённый `h2` без явного `cy.reload()`). Тикет переведён в
  «Готово», файл удалён.

## Отклонено как не баг (файл удалён)

- **BUG-024** (`PUT /v3/profile` отвечает `204` на цифры/HTML в
  Имени/Фамилии, но тихо НЕ сохраняет значение, Jira AS-4528) —
  технически поведение подтверждено воспроизводимым при перепроверке
  2026-08-10 (curl напрямую + автотест, оба раза `204` вместо ожидаемого
  `422`, значение не применяется). Тем не менее по прямому решению
  пользователя 2026-08-10 это исключение для данного конкретного
  эндпоинта признано ожидаемым поведением, не дефектом — файл удалён,
  автотесты в `edit_profile.cy.js` переведены из "падает, пока не почини"
  в "фиксирует принятый контракт" (см. describe «цифры/HTML в имени
  приняты сервером без ошибки»). **Уточнение 2026-08-10:** тикет AS-4528
  на самом деле уже существовал в Jira (обнаружено при разборе BUG-025) и
  уже был в статусе «Не актуален» — `jira-mapping.json` не содержит записи
  ни для одного бага из этой папки, он неполный/устаревший для
  `edit_profile/`, не полагаться на его отсутствие как на признак
  «в Jira не заводился».
- **BUG-028** («При открытии модалки тело формы ~0.5–0.9с абсолютно
  пустое», Jira AS-4533) — уточнено пользователем 2026-08-10: форма
  ожидаемо подгружает поля с бэка (`GET /v3/profile`), короткая пауза перед
  их появлением — не баг, отдельный скелетон не требуется. Перепроверено
  живьём в тот же день через `MutationObserver` — интервал (~470–520мс)
  подтверждён технически неизменным, но признан приемлемым поведением, не
  дефектом. Тикет переведён в «Не актуален», файл удалён.

Нумерация продолжает `../coupons/` (BUG-017..019), НО пропускает
BUG-020..023 и BUG-027 — они заняты параллельной сессией под

## Автотест

`cypress/e2e/main_test/cabinet/edit_profile.cy.js`, page object
`cypress/support/pageObjects/editProfilePage.js`, API-хелперы
`getProfile`/`putProfile`/`profileFieldsMap` в `cabinetApi.js`.

25 тестов. После того как BUG-024 признан не багом (2026-08-10), связанные
с ним 3 теста переведены из «падает, пока не почини» в «фиксирует принятый
контракт» (ожидают `204` + прежнее значение вместо `422`) — они теперь
стабильно **passing**. BUG-025 исправлен (2026-08-10) — тест на живое
обновление карточки без reload теперь тоже проходит сам по себе, без
правок (обновление укладывается в стандартный retry-таймаут `cy.should`).
Осталось 1 намеренное падение, соответствующее ещё открытому BUG-026
(неверный текст ошибки).

Тост «Успешно» на странице сам скрывается через несколько секунд
(auto-dismiss), из-за чего надёжно проверить его ОТСУТСТВИЕ через
`.should('not.exist')` невозможно — эта проверка на разных прогонах давала
то ложный pass (проверили раньше, чем тост успел появиться), то ложный pass
по другой причине (проверили уже после того как он сам исчез). Там, где
нужно зафиксировать факт показа тоста, используем позитивную проверку
`.should('be.visible')` со встроенным retry.

## Разведка сети (открытие/сохранение/обновление)

Полная разведка реального контракта — в памяти проекта
(`project_lk_testing_d2_stand`), кратко:
- Открытие модалки: `GET /v3/profile` → `{fields:[{name,label,placeholder,
  type,value,validation[],data{}}]}`.
- Сохранение: `PUT /v3/profile` (не POST/PATCH), тело
  `{firstname,lastname,birthdate,gender,email}` — `gender` строкой,
  `contact_phone` не отправляется. Успех — `204` без тела.
- Обновление: фронт сам делает повторный `GET /v3/profile` сразу после
  успешного `PUT` — карточка ФИО в сайдбаре и шапка сайта тоже обновляются
  без reload, но с задержкой ~1-2 сек относительно самой модалки (было
  BUG-025, исправлено).
- Реальная серверная валидация 422 подтверждена корректной для:
  пустое/пробелы-only firstname/lastname, будущая дата рождения, битый
  email, gender вне `{1,2}` — исключение «цифры/HTML в имени» (было
  BUG-024) сервер вместо `422` тихо принимает с `204` без применения
  значения, но это признано ожидаемым поведением (см. выше), не багом;
  также кроме отображения на UI (BUG-026 — сервер прав, фронт неверно
  показывает ошибку).

## Что НЕ было протестировано (и почему)

- **Прямой ввод даты рождения через календарь** (TC-029..041) — поле
  «Дата рождения» на самом деле не текстовый инпут, а кнопка-триггер
  календаря (Reka UI popover); сложные сценарии переключения месяцев/лет
  не автоматизированы, только базовое отображение и серверная валидация
  границы (будущая дата) — через прямой API, как и рекомендует сам xlsx
  (Примечание №11).
- **Email-уникальность** (TC-060/TC-API-027) — xlsx предполагает, что
  `test@mail.com` уже занят другим аккаунтом; на этом стенде это не
  подтвердилось (email сохранился без ошибки) — нужен реальный второй
  зарегистрированный аккаунт, чтобы проверить это по-настоящему.
- **27 кейсов «Комбинации полей»** (TC-CMB-001..027) — покрыта только
  показательная часть (TC-CMB-001-класс — комбинированное сохранение
  нескольких валидных полей за один запрос); полная матрица
  валидно/невалидно по всем 5 полям не автоматизирована — типовой паттерн
  (частичная валидация блокирует всю форму) уже виден в TC-006/TC-007/
  BUG-026 тестах и распространяется на комбинации логически так же.
