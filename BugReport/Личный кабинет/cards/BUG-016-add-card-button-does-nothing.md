# BUG-016: Клик «+ Добавить карту» открывает модалку с полностью пустым (белым) содержимым

**Раздел:** Личный кабинет — Мои карты (`/cabinet/cards/`), добавление карты
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/cards/` (тестовый стенд d2)

## Предусловия

Пользователь авторизован, находится на `/cabinet/cards/`.

## Шаги воспроизведения

1. Открыть `/cabinet/cards/`.
2. Кликнуть по кнопке «+ Добавить карту».
3. Наблюдать за страницей, консолью и сетевыми запросами.

## Ожидаемый результат

Согласно TC-МО-21, клик должен открывать форму ввода данных карты (как
правило — защищённый iframe платёжного провайдера) для привязки новой
карты.

## Фактический результат

Уточнено повторной проверкой (включая скриншот, полученный от пользователя
при собственном воспроизведении): клик **открывает модальное окно**
(с крестиком закрытия в правом верхнем углу), НО тело модалки полностью
**пустое/белое** — ни формы ввода данных карты, ни видимого iframe
платёжного провайдера, ни текста ошибки, ни индикатора загрузки. Модалка
остаётся пустой бессрочно (не подгружается со временем).

При первой проверке через автоматизированный клик в headless-сессии
модалка не появлялась вовсе (возможно, из-за particularities автоматизации
или таймингов загрузки iframe) — но подтверждённое реальным пользователем
поведение однозначно: модалка открывается, содержимое — пустой белый
блок. В консоли браузера при этом не появляется ошибок, кроме фоновых
предупреждений аналитики, не связанных с действием.

**Важная оговорка:** нельзя полностью исключить, что это ограничение
именно тестового стенда `d2.im.mdev.kz` (напр. интеграция с платёжным
провайдером специально отключена/не настроена в тестовом окружении) — но
с точки зрения приёмочного тестирования это всё равно нарушение требуемой
функции («клик по кнопке должен инициировать добавление карты»), а не
просто отсутствие данных. Стоит уточнить у разработчиков, ожидаемо ли
такое поведение конкретно на этом стенде.

## Вероятная причина

Модалка успешно открывается (обработчик клика подключён корректно). Внутри
неё обнаружен `<iframe class="zoid-visible" title="custom_iframe_loader">`
— «zoid» — известный фреймворк для встраивания кросс-доменных виджетов
(используется, например, PayPal/аналогичными платёжными провайдерами для
безопасной токенизации карты). У этого iframe **пустой атрибут `src`** —
то есть фронт корректно подготовил обёртку для виджета провайдера, но так
и не подставил в неё URL. Похоже на отсутствующую/пустую конфигурацию
(merchant ID, URL провайдера и т.п.) именно для тестового окружения
`d2.im.mdev.kz`, без явной обработки этого случая как ошибки — вместо
сообщения пользователю модалка просто остаётся пустой.
