# BUG-011: Несогласованный пробел в плашках «+ N бонусов» (с пробелом) vs «+N фишек» (без пробела)

**Раздел:** Личный кабинет — Бонусы и фишки (`/cabinet/bonuses/`), карточка операции
**Severity:** Low
**Приоритет:** Low
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/bonuses/` (тестовый стенд d2)

## Предусловия

Заказ с ненулевыми `all_bonuses` и `all_chips` одновременно (напр. № 5008:
`all_bonuses: 209`, `all_chips: 1`).

## Шаги воспроизведения

1. Открыть `/cabinet/bonuses/`.
2. Найти карточку заказа с обеими плашками (бонусы и фишки) одновременно.
3. Сравнить форматирование текста в зелёной плашке бонусов и розовой
   плашке фишек.

## Ожидаемый результат

Обе плашки однотипны по смыслу (положительное начисление) и получают
одинаково «чистые» числовые значения из API (`all_bonuses`/`all_chips` —
обычные числа без форматирующих символов) — форматирование должно быть
идентичным.

## Фактический результат

Плашка бонусов: **«+ 209 бонусов»** (с пробелом после «+»).
Плашка фишек: **«+1 фишек»** (без пробела после «+»).

Подтверждено на заказе № 5008 (`all_bonuses: 209`, `all_chips: 1`), а также
на других карточках: «+ 71 бонусов» (пробел) vs «+44 фишек», «+45 фишек»
(без пробела) — паттерн систематический, не случайность на одной карточке.

## Вероятная причина

Разные компоненты/шаблоны для плашки бонусов и плашки фишек с разным
хардкодом пробела в строке форматирования — чисто фронтовая
несогласованность стилей, не связанная с данными API.

## Автотест, фиксирующий баг

`cypress/e2e/main_test/cabinet/bonuses.cy.js` — тест сверяет текст обеих
плашек на карточке с ожидаемым единообразным форматом и падает, пока баг не
исправлен.
