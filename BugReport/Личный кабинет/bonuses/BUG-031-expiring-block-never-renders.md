# BUG-031: Блок «X бонусов/фишек сгорят [дата]» никогда не отображается — фронтенд игнорирует `nearest_expiration_date`/`expiration_total`, даже когда они заполнены

**Раздел:** Личный кабинет — Бонусы и фишки (`/cabinet/bonuses/`), блок «Ваш баланс»
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата:** 2026-08-10
**Окружение:** `http://d2.im.mdev.kz/cabinet/bonuses/`, API `http://api.d.im.mdev.kz`

## Предусловия

`GET /v2/personal/bonuses-history` отдаёт `data.all_data.nearest_expiration_date` /
`data.all_data.expiration_total` (и аналогично `data.chips.*`) — поля явно
предназначены для блока предупреждения о сгорании бонусов/фишек (см.
TC-БО-7/TC-БО-8 в `TestPlans/LK-full-testcases.md`).

На реальных данных аккаунта оба поля сейчас пустые (`""`/`0`) — блок
корректно скрыт (это уже покрыто отдельным тестом TC-БО-8, баг не про этот
случай).

## Шаги воспроизведения

1. Открыть `/cabinet/bonuses/`, авторизовавшись (`cy.loginD2()`/сессия
   Джон Appleseed).
2. Перехватить/подменить `window.fetch` так, чтобы ответ
   `bonuses-history` возвращал реалистичные непустые значения:
   `all_data.nearest_expiration_date: "15.09.2026"`,
   `all_data.expiration_total: 12345`, аналогично для `chips`
   (`"15.09.2026"` / `42`).
3. Перейти на страницу «Бонусы и фишки» через SPA-навигацию (клик по
   пункту меню, не полный `reload`, чтобы патч `fetch` не терялся).
4. Проверить, что запрос ДЕЙСТВИТЕЛЬНО вернул подменённые данные (прямой
   повторный `fetch()` на этой же странице после рендера подтвердил:
   `{"all_data":{"nearest_expiration_date":"15.09.2026","expiration_total":12345},"chips":{"nearest_expiration_date":"15.09.2026","expiration_total":42}}`).
5. Проверить видимый текст страницы на наличие блока сгорания.

## Ожидаемый результат

При непустых `nearest_expiration_date`/`expiration_total` отображается блок
«X бонусов сгорят [дата]» и «X фишек сгорят [дата]» рядом с блоком «Ваш
баланс» (аналогично тому, как для той же карточки корректно отображается
плашка «N списано», управляемая похожим по духу полем — см. ниже).

## Фактический результат

Блок «Ваш баланс» рендерится как «0 бонусов / 0 фишек» без какого-либо
текста про сгорание — `document.body.innerText` не содержит подстроки
«сгор» вообще, при том что подменённый ответ API, гарантированно дошедший
до фронтенда (проверено повторным прямым запросом со страницы ПОСЛЕ
рендера — см. шаг 4), содержит валидные непустые значения обоих полей.

Для контроля методики та же самая техника подмены ответа (`window.fetch`
override + SPA-переход, без релоада) в этой же сессии ДЕЙСТВИТЕЛЬНО
изменила рендер, когда был подменён другой, структурно аналогичный флаг —
`products[].spent_bonuses` (используется для плашки «N списано»): плашка
«500 списано» появилась на карточке ровно там, где и ожидалось. Это
исключает версию «подмена не сработала» — фронтенд в принципе реагирует на
подменённые данные этого же ответа, но конкретно для
`nearest_expiration_date`/`expiration_total` — нет.

## Скриншоты

`screenshots/bug-031-no-expiring-block-despite-mocked-data.jpg` — страница
«Бонусы и фишки» с подменённым (непустым) `nearest_expiration_date`/
`expiration_total`, блок «Ваш баланс» показывает «0 бонусов / 0 фишек» без
намёка на текст о сгорании.

## Вероятная причина

Похоже, что верстка/логика блока «X сгорят [дата]» либо не реализована на
фронтенде вовсе (задел под неё есть только в бэкенд-контракте), либо
завязана на какое-то ДРУГОЕ поле/условие, отличное от
`nearest_expiration_date`/`expiration_total` — в любом случае сейчас блок
недостижим ни при каких значениях этих полей, а значит бесполезен даже
если бэкенд когда-нибудь начнёт отдавать в них реальные даты.

## Автотест, фиксирующий баг

`cypress/e2e/main_test/cabinet/bonuses.cy.js` — TC-БО-7 подменяет ответ
`bonuses-history` через `cy.intercept()` на непустые
`nearest_expiration_date`/`expiration_total` и ожидает появления блока
сгорания; тест падает, пока баг не исправлен.
