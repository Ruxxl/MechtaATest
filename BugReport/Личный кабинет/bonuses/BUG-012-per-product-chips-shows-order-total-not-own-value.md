# BUG-012: В развёрнутых деталях заказа каждый товар показывает ОБЩУЮ сумму начисления заказа вместо своего earned_chips/earned_bonuses

**Раздел:** Личный кабинет — Бонусы и фишки (`/cabinet/bonuses/`), развёрнутая карточка операции
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-07
**Окружение:** `http://d2.im.mdev.kz/cabinet/bonuses/` (тестовый стенд d2), API `http://api.d.im.mdev.kz`

## Предусловия

Заказ с несколькими товарами, у каждого — своё индивидуальное значение
`earned_chips`/`earned_bonuses`, отличное от значений других товаров того
же заказа. Пример: заказ № 10394549 (`GET
/v2/personal/bonuses-history?page=1&limit=10`), 2 товара:
- «Фильтр для воды АКВАФОР А-5 (3+1)» — `earned_chips: 1`
- «Смартфон Apple iPhone 15 128GB (Pink)» — `earned_chips: 44`
- Сумма заказа `all_chips: 45` (1+44=45 — арифметика верна на уровне API).

## Шаги воспроизведения

1. Открыть `/cabinet/bonuses/`.
2. Найти карточку заказа № 10394549 (или любую другую с несколькими
   товарами и РАЗНЫМИ earned_chips/earned_bonuses по товарам).
3. Кликнуть «Показать детали».
4. Сравнить число в плашке у каждого из товаров с полем
   `products[].earned_chips` (или `earned_bonuses`) этого же товара в
   ответе API.

## Ожидаемый результат

Каждая строка товара в развёрнутом виде должна показывать СВОЁ
индивидуальное начисление — «+1 фишек» у фильтра для воды и «+44 фишек» у
смартфона (именно это описывает TC-БО-27 как ожидаемое поведение).

## Фактический результат

**Обе** строки товара показывают одно и то же число — **«+45 фишек»**
(общую сумму заказа `all_chips`), продублированную на каждой позиции,
вместо индивидуальных `earned_chips: 1` и `earned_chips: 44`. Пользователь
не может понять, сколько фишек реально начислено за каждый конкретный
товар — цифра на обеих строчках одинаковая и не соответствует ни одному из
двух реальных значений по отдельности.

## Скриншоты

- `screenshots/bug012-duplicated-order-total-per-product.png` — заказ

## Вероятная причина

Компонент строки товара в развёрнутом виде, похоже, привязан к полю
`all_chips`/`all_bonuses` заказа (одно значение на весь массив `products`)
вместо `products[i].earned_chips`/`earned_bonuses` каждого конкретного
элемента — классическая ошибка привязки данных, когда для итерации по
массиву используется значение родителя вместо значения текущего элемента.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/cabinet/bonuses.cy.js` — тест разворачивает
заказ с несколькими товарами и разными earned_chips/earned_bonuses, сверяет
каждую строку с её собственным значением из API и падает, пока баг не
исправлен.
