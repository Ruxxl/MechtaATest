# BUG-001: При ошибке `GET /api/v2/header/cities` кнопка текущего города пропадает из шапки

**Раздел:** Главная страница (`https://pp.yc.mechta.kz/`) — Хедер
**Severity:** Low
**Приоритет:** Low
**Статус:** Подтверждён
**Дата:** 2026-08-18
**Окружение:** `https://pp.yc.mechta.kz/`, автотест (mock `500` на `GET /api/v2/header/cities`)

## Предусловия

`GET /api/v2/header/cities` отвечает ошибкой (в тесте — форсированный `500`).

## Шаги воспроизведения

1. Замокать `GET /api/v2/header/cities` так, чтобы он возвращал `500`.
2. Открыть главную страницу.
3. Осмотреть левый верхний угол шапки, где обычно отображается кнопка с
   названием текущего выбранного города («Астана»).

## Ожидаемый результат

Название текущего выбранного города в шапке должно оставаться видимым
независимо от результата запроса за ПОЛНЫМ списком городов — это два разных
назначения одного эндпоинта: (1) показать, какой город выбран сейчас
(обычно известно заранее — из cookie/localStorage/предыдущего рендера), и
(2) отдать полный список для модалки выбора нового города. Сбой второго не
должен ломать первое.

## Фактический результат

Кнопка с текущим городом полностью пропадает из шапки (на её месте —
пустота/дефис), хотя остальная шапка (логотип, поиск, счётчики, ссылки)
продолжает нормально отображаться.

## Скриншоты

`screenshots/bug001-city-disappears-on-cities-api-500.png`

## Вероятная причина

Судя по всему, отображение названия текущего города во фронтенде завязано
на успешный ответ `GET /api/v2/header/cities` целиком (та же загрузка
данных, что и для модалки выбора), а не на отдельно сохранённое/кэшированное
значение уже известного текущего города.

## Автотест, фиксирующий баг

`cypress/e2e/main_test/home_page/header.cy.js` → describe «Главная — Хедер:
негативные сценарии (обработка ошибок API)» → `GET /api/v2/header/cities —
500 не убирает текущий выбранный город из шапки`. Тест фиксирует ОЖИДАЕМОЕ
поведение и должен падать, пока баг не исправлен.
