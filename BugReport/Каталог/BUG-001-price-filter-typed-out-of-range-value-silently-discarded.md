# BUG-001: Значение цены, введённое вручную за пределами текущего диапазона слайдера, молча отбрасывается без уведомления пользователя

**Раздел:** Каталог — фильтр «Цена» на странице категории (например `/section/smartfony/`)
**Severity:** Low
**Приоритет:** Low
**Статус:** Подтверждён
**Дата:** 2026-08-20
**Окружение:** `https://pp.yc.mechta.kz/`

## Предусловия

Открыта любая страница категории каталога с фильтром «Цена» (слайдер + два числовых
поля «От»/«До»).

## Шаги воспроизведения

1. Открыть `/section/smartfony/`, применить любой фильтр, сужающий диапазон цен
   слайдера (например бренд VIVO + «Есть скидка» → слайдер сужается до 59 990–679 990).
2. Кликнуть в поле «От», ввести значение, заведомо превышающее текущий максимум
   слайдера (например `2000000`).
3. Нажать Enter или кликнуть «Показать N результатов».

## Ожидаемый результат

Один из вариантов корректной обработки: значение либо отклоняется с понятной подсказкой
(«Максимум N ₸»), либо автоматически ограничивается (clamp) до фактического максимума
слайдера — в любом случае пользователь должен понимать, что произошло с его вводом.

## Фактический результат

Введённое значение **молча отбрасывается**: после применения фильтра поле «От»
возвращается к своему прежнему валидному значению (или к абсолютному минимуму слайдера
на промежуточном кадре загрузки) — без какой-либо подсказки, ошибки или визуальной
индикации, что значение `2000000` было отклонено. Пользователь, напечатавший число,
может не заметить, что оно не применилось, и ошибочно решить, что в категории просто
нет товаров дороже уже применённого диапазона.

Дополнительно замечено: во время самого перехода (между кликом «Показать» и загрузкой
результатов) поле «От» на короткое время показывает `59 990` (абсолютный минимум
слайдера) — значение, отличное как от отброшенного ввода, так и от фактически
применённого фильтра (`minPrice=300000` в URL/результатах) — то есть в переходном кадре
поле визуально показывает третье, ещё более сбивающее с толку значение. После полной
загрузки поле само корректируется и синхронизируется с реально применённым значением.

## Скриншоты

`screenshots/bug001-price-input-typed-value-ignored.jpg` — введено `2 000 000` в поле
«От», слайдер не сдвинулся (диапазон остался прежним).

использовано предыдущее валидное значение (`300 000`, видно в URL `minPrice=300000`),
а не введённые `2 000 000`.

## Вероятная причина

Валидация значения поля «От»/«До», судя по всему, происходит через сравнение с текущими
`min`/`max` атрибутами слайдера (которые зависят от уже применённых фильтров) — при
значении вне этого диапазона обработчик просто не обновляет state вместо явного
clamp/показа ошибки, из-за чего инпут визуально "откатывается" к последнему валидному
значению без обратной связи для пользователя.

Автотеста нет — найдено при целевой проверке комбинаций фильтров (граничные значения)
по запросу пользователя, живьём на `pp.yc.mechta.kz`, 2026-08-20.
