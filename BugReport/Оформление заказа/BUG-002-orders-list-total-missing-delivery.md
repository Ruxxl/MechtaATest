# BUG-002: В списке «Мои заказы» сумма неоплаченного заказа с курьерской доставкой показывает только стоимость товаров, без учёта доставки

**Раздел:** Оформление заказа / Личный кабинет → Мои заказы (`/cabinet/orders/`, `GET /v2/personal/orders_list`)
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата:** 2026-08-19
**Окружение:** `http://pp.im.mdev.kz/`, API `http://api.pp.im.mdev.kz`

## Предусловия

Авторизованный пользователь (Appleseed John, телефон 0000000000). Оформлен заказ с
курьерской доставкой (платная зона «Доставка по г.Астана», 1000 ₸) и способом оплаты
«Картой онлайн», редирект на эквайер не завершён реальной оплатой — заказ висит в
статусе `waiting_for_payment` («Оплата не прошла, деньги не списались»).

## Шаги воспроизведения

1. В корзине — 1 товар (Батарейка CAMELION CR1632, 390 ₸).
2. Чекаут: способ доставки «Доставка», зона «Доставка по г.Астана» (1000 ₸), способ
   оплаты «Картой онлайн». Подтвердить заказ, не завершать оплату на эквайере (или
   заказ просто остаётся неоплаченным).
3. Открыть `/cabinet/orders/` (вкладка «Активные»).
4. Сравнить сумму в шапке карточки заказа с суммой на кнопке «Оплатить N ₸» внутри той
   же карточки.

Воспроизведено дважды подряд на двух разных заказах (№10396412, №10396410 — оба:
товар 390 ₸ + доставка 1000 ₸).

## Ожидаемый результат

Сумма в шапке карточки заказа в списке «Мои заказы» должна совпадать с реальной суммой
к оплате этого заказа (`payment_info.total`/`to_pay` в API, она же показана на кнопке
«Оплатить» внутри той же карточки) — то есть включать стоимость доставки.

## Фактический результат

Шапка карточки показывает **390 ₸** (это `basket.total_prices.discounted_price` —
только сумма товаров), а кнопка «Оплатить» в той же карточке — **1 390 ₸** (корректная
полная сумма). Реальная сумма к оплате по API:

```json
{
  "current_status": "waiting_for_payment",
  "basket_total": 390,
  "delivery_type": "courier",
  "delivery_pay": 1000,
  "payment_total": 1390
}
```

Одна и та же карточка заказа одновременно показывает два разных числа как «сумму
заказа» — вводит пользователя в заблуждение относительно реальной стоимости покупки.

У заказов с самовывозом (доставка = 0 ₸) баг не проявляется визуально, поскольку сумма
товаров и полная сумма к оплате в этом случае совпадают — но это тот же неверный
источник данных, просто маскируемый нулевой доставкой.

`screenshots/bug002-orders-list-wrong-total-no-delivery.jpg` — список «Мои заказы»,

## Вероятная причина

Список заказов (`/v2/personal/orders_list`) на фронтенде, судя по всему, берёт сумму
для отображения в шапке карточки из `basket.total_prices.discounted_price`, а не из
`order.payment_info.total` — то есть не учитывает стоимость доставки для ещё не
завершённых (`waiting_for_payment`) заказов. Кнопка «Оплатить» внутри той же карточки,
судя по всему, использует другой, корректный источник данных.

## Автотест, фиксирующий баг

`cypress/e2e/regress_test/orders_list_total_bug_pp_im.cy.js` — создаёт реальный заказ
(курьерская доставка, 1000 ₸ + товар 390 ₸) через UI чекаута, затем сверяет сумму в
шапке карточки этого заказа в `/cabinet/orders/` с `payment_info.total`. Стабильно
падает на ожидаемом месте (`-390 +1390`), 2 прогона подряд.
