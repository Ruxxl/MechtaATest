# BUG-001: Промокод, применённый один раз, навсегда «прилипает» к корзине аккаунта и автоматически применяется к любым новым, не связанным с ним товарам

**Раздел:** Оформление заказа / Корзина (`/basket/`, `GET /api/v2/basket`)
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата:** 2026-08-12
**Окружение:** `http://d5.im.mdev.kz/`, API `http://api.d5.im.mdev.kz`

## Предусловия

Авторизованный пользователь (Джон Appleseed, телефон 0000000000) один раз вводит и
применяет промокод/купон `ME232PR` («тест 10к сайт», скидка 10 000 ₸) в корзине с одним
товаром, доводит заказ до оплаты.

## Шаги воспроизведения

1. В корзине с товаром А ввести и применить промокод `ME232PR` в поле «Введите
   промокод/купон». Оформить и оплатить заказ (промокод отработал корректно, всё ожидаемо).
2. В любой ПОЗЖЕ открытой сессии того же аккаунта полностью очистить корзину (например,
   оформив заказ, после чего она становится пустой) и добавить туда СОВЕРШЕННО ДРУГОЙ,
   не связанный товар (в тесте — микроволновая печь MIDEA MM 7P012 MZ Black,
   артикул 11185), ни разу не вводя промокод заново.
3. Открыть `/basket/`.

Дополнительно воспроизведено через прямой API-запрос:

```bash
curl -s -b cookies.txt "http://api.d5.im.mdev.kz/v2/basket" \
  -H "Accept: application/json" | jq '.data.coupon_list, .data.discount_by_coupons'
```

## Ожидаемый результат

Промокод — это разовое действие пользователя для конкретной покупки. После оформления
заказа, где он был использован, промокод не должен автоматически переноситься и
применяться к последующим, никак не связанным с ним корзинам без явного повторного
ввода пользователем (или явно должен быть представлен как «активированная скидочная
карта» с понятным пользователю статусом/сроком, а не как одноразовый промокод).

## Фактический результат

Товар «Микроволновая печь MIDEA MM 7P012 MZ Black» (база 29 990 ₸) добавлен в **пустую**
корзину без какого-либо повторного ввода промокода. Тем не менее корзина сразу
показывает скидку -10 000 ₸ от промокода `ME232PR`:

- В UI корзины: «Выгода -10 000 ₸ · Промокод ME232PR -10 000 ₸», Итого **19 990 ₸**
  вместо 29 990 ₸.
- В блоке «Программа лояльности» промокод отображается как отдельный переключатель
  «тест 10к сайт / ME232PR», включённый (ON) по умолчанию.
- В `GET /v2/basket` купон присутствует и активен:

```json
"coupon_list": [
  {
    "applied": true,
    "available_to": "до ",
    "code": "ME232PR",
    "discount": 10000,
    "name": "тест 10к сайт"
  }
],
"discount_by_coupons": 10000
```

Поведение воспроизведено дважды подряд на двух разных, не связанных друг с другом
корзинах/товарах (Infinix Note 50 с подарками и позже — микроволновая печь) — то есть
не единичный сбой, а стабильно повторяющееся поведение.

Дополнительно замечено (не самостоятельный баг, но артефакт той же записи): поле
`available_to` в объекте купона равно `"до "` — с обрезанной/отсутствующей датой после
пробела, хотя в UI купон отображается без ограничения по сроку.

`screenshots/bug001-sticky-promocode-new-cart.jpg` — пустая до этого корзина с

## Вероятная причина

Похоже, купон привязывается на бэкенде не к конкретному заказу/сессии его применения, а
постоянно (permanently) к аккаунту пользователя — как активированная скидочная карта —
и затем безусловно переприменяется к любой будущей корзине этого аккаунта, пока его явно
не выключат переключателем «Программа лояльности». Технически это может быть и
осознанной механикой (аналог подключаемой скидочной карты), но для промокода с семантикой
«тест 10к сайт» / коротким буквенно-цифровым кодом, вводимого через поле «промокод»,
такое постоянное закрепление не ожидается и вводит в заблуждение — учёт скидки по
конкретному заказу становится непрозрачным.

## Автотест, фиксирующий баг

Автотеста нет — найдено при ручном сквозном тестировании чекаута (оплата картой, разные
способы доставки, подарки, бонусы, промокоды) на стенде d5.im.mdev.kz.
