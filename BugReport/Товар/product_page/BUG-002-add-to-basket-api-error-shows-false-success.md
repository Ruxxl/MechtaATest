# BUG-002: Ошибка API при добавлении в корзину не обрабатывается — показывается ложный успех с невидимой сломанной панелью

**Раздел:** Страница товара — кнопка «В корзину» / панель сопутствующих товаров
**Severity:** High
**Приоритет:** High
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-05
**Окружение:** `https://pp.yc.mechta.kz/product/smartfon-apple-iphone-15-128gb-pink/`

## Предусловия

Любой товар с непустой панелью сопутствующих товаров (см. `fixtures.inStock`). Для
воспроизведения `POST /api/v2/basket/add` замокан на ответ `500` (`cy.intercept`).

## Шаги воспроизведения

1. Открыть страницу товара.
2. Замокать `POST /api/v2/basket/add` так, чтобы он отвечал `500`.
3. Нажать «В корзину».

## Ожидаемый результат

Один из вариантов корректной обработки ошибки:
- Показывается явное сообщение об ошибке («Не удалось добавить товар», «Попробуйте
  ещё раз» и т.п.), товар не отмечается как добавленный;
- Панель успеха вообще не открывается.

## Фактический результат

Панель «Товар добавлен в корзину» **монтируется в DOM в состоянии `data-state="open"`**
со всем ожидаемым содержимым (название товара, цена, вкладки сопутствующих категорий),
как будто запрос выполнился успешно — несмотря на реальный ответ `500`. При этом:

- Сама панель **визуально не видна** — она остаётся вне экрана (сломана анимация
  появления `slide-in-from-right`, которая, судя по всему, применяется только при
  переходе `closed → open`, а не при монтировании сразу в состоянии `open`);
- Тёмный оверлей-подложка (`data-slot="overlay"`, `bg-black/60`, `pointer-events: auto`)
  при этом **виден и активен**, блокируя клики по странице — пользователь видит
  затемнённый экран без какого-либо текста и без возможности понять, что произошло;
- Никакого сообщения об ошибке не показывается — с точки зрения бэкенда товар не
  добавлен (реальный запрос вернул 500), но UI никак это не отражает;
- `Esc` корректно закрывает скрытую панель и снимает оверлей, после чего страница
  снова полностью интерактивна — состояние восстановимо, но требует от пользователя
  «угадать» `Esc`, поскольку на экране нет ни одной подсказки, что произошло что-то
  нештатное.

Воспроизведено стабильно через `cy.intercept` + прямую проверку DOM
(`data-state`, `getComputedStyle`, скриншот) — не зависит от конкретного товара,
привязано к обработке ответа `POST /api/v2/basket/add`.

## Скриншоты

- `screenshots/bug002-invisible-panel-blocking-overlay.png` — состояние экрана через
  2с после клика «В корзину» с замоканной ошибкой 500: видна только затемнённая

  присутствует `[role="dialog"] data-state="open"` с полным содержимым панели).

## Вероятная причина

Обработчик клика «В корзину», похоже, не проверяет `status`/`ok` ответа запроса
добавления и открывает панель успеха по самому факту завершения запроса (а не по
факту успеха). Отдельно, анимация появления панели триггерится только на переходе
`state: closed → open` (React/Vue transition on change), а не при первом монтировании
сразу в открытом состоянии — из-за этого визуально панель не показывается, хотя логически
как бы «открыта».

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/product_page/cart_crosssell.cy.js` → тесты на ошибку
добавления в корзину (TC-CART-03, TC-CART-05) — целенаправленно проверяют ОЖИДАЕМОЕ
поведение (видимое сообщение об ошибке, отсутствие ложной панели успеха) и падают,
документируя баг.
