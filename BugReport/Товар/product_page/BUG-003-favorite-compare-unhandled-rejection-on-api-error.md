# BUG-003: Ошибка API при добавлении в избранное/сравнение вызывает необработанное исключение (unhandled promise rejection)

**Раздел:** Страница товара — иконки «Избранное» и «Сравнение»
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-05
**Окружение:** `https://pp.yc.mechta.kz/product/smartfon-apple-iphone-15-128gb-pink/`

## Предусловия

Любой товар. `POST /api/v3/favorites/add` (для избранного) или `POST /api/v2/compare`
(для сравнения) замокан на ответ `500` (`cy.intercept`).

## Шаги воспроизведения

1. Открыть страницу товара.
2. Замокать `POST /api/v3/favorites/add` (или `POST /api/v2/compare`) так, чтобы он
   отвечал `500` с телом `{"error":"internal"}`.
3. Кликнуть иконку «Избранное» (сердце) или «Сравнение» (весы).

## Ожидаемый результат

Ошибка сети/бэкенда корректно перехватывается кодом приложения: либо оптимистично
изменённая иконка откатывается назад к исходному состоянию, либо показывается
явное сообщение об ошибке пользователю — в любом случае без падения JS-контекста
страницы.

## Фактический результат

Приложение выбрасывает **необработанное исключение** (unhandled promise rejection) с
телом ответа сервера как есть: `Error: {"_data":{"error":"internal"}}`. Это означает,
что промис запроса добавления не обёрнут в `.catch()`/`try-catch` — ошибка утекает
в глобальный `window.onunhandledrejection`, что в реальном браузере пользователя
проявляется как молчаливая ошибка в консоли, без какой-либо обратной связи на экране
(ни отката иконки, ни сообщения). Воспроизведено идентично для обеих иконок
(«Избранное» и «Сравнение») — общий паттерн необработанной ошибки в обработчиках
обеих кнопок.

Тот же класс дефекта, что и **BUG-002** (корзина) — обработчики click-действий на
странице товара систематически не оборачивают запрос в try/catch с корректной
обработкой неуспешного ответа.

- `screenshots/bug003-unhandled-rejection.png` — Cypress-раннер в момент падения
  теста: команда `wait @favAddErr` выполнена успешно (запрос реально вернул 500),
  но сразу следом — необработанное исключение с телом ответа сервера.

## Вероятная причина

Обработчики клика по иконкам избранного/сравнения используют `fetch(...)` напрямую и,
похоже, не проверяют `response.ok`/`status` перед тем как либо продолжить (оптимистичное
обновление остаётся неподтверждённым), либо выбрасывают сырой объект ответа без
`.catch()` на вызывающей стороне.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/product_page/product_page/favorites_compare.cy.js` → негативные кейсы
ошибки API при добавлении в избранное/сравнение — целенаправленно проверяют ОЖИДАЕМОЕ
поведение (нет необработанного исключения, есть корректная реакция UI) и падают,
документируя баг.
