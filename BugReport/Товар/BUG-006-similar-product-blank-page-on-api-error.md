# BUG-006: Переход на карточку похожего товара при ошибке API — пустая страница вместо 404

**Раздел:** Страница товара — блок "Похожие товары"
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён
**Дата обнаружения:** 2026-08-05
**Окружение:** `https://pp.yc.mechta.kz/product/smartfon-apple-iphone-15-128gb-pink/`

## Предусловия

Страница товара с непустым блоком "Похожие товары" (данные — `/api/v3/product/{slug}/alternatives`).

## Шаги воспроизведения

1. Открыть страницу товара с блоком "Похожие товары".
2. Кликнуть по карточке любого похожего товара (переход на `/product/{targetSlug}/`).
3. Смоделировать ситуацию, когда бэкенд для целевого товара недоступен —
   `GET /api/v3/product/{targetSlug}` отвечает ошибкой (в тесте — замокан `500`).

## Ожидаемый результат

Согласно формулировке исходного тест-плана (TC-SIM-02) и уже установленному в проекте
паттерну для недоступного раздела/товара (см. `breadcrumbs_and_gallery.cy.js` —
"НЕГАТИВ (аналог TC-BC-03)", `sticker_and_availability.cy.js` — "Несуществующий
товар"): должна отобразиться страница 404 с текстом "Мы не можем найти то, что Вы
ищете" и ссылкой на главную.

## Фактический результат

URL корректно меняется на `/product/{targetSlug}/` (переход происходит), но
**основная область контента страницы полностью пустая** — ни карточки товара, ни
текста "Мы не можем найти то, что Вы ищете", ни какого-либо другого сообщения об
ошибке. Видны только шапка и футер сайта. Пользователь оказывается на "битой"
странице без объяснения причины и без явного пути вернуться (кроме шапки/футера).

Важно: при переходе на ДЕЙСТВИТЕЛЬНО несуществующий товар (реальный 404 от API, не
500) страница показывает корректное сообщение "Мы не можем найти то, что Вы ищете" —
то есть обработка есть, но только для одного конкретного кода ответа/сценария, а не
для ошибок API в целом.

## Вероятная причина

Обработка "не найдено" в клиентском коде страницы товара, похоже, завязана на
конкретный признак настоящего 404 (например, конкретный код ошибки API), а не на
общий catch для любой ошибки загрузки данных товара — при любой ДРУГОЙ ошибке (500,
таймаут и т.п.) отображается просто пустой результат рендера без какого-либо fallback
UI.

## Автотест, фиксирующий баг

`cypress/e2e/Regress_Test/product_page/similar_products.cy.js` → TC-SIM-02 — тест
целенаправленно проверяет ОЖИДАЕМОЕ поведение (страница 404 с сообщением) и падает,
документируя баг.
