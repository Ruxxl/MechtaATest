## Что НЕ было оформлено как баг (и почему)

> Обновление 2026-08-04: критерий бага расширен — некорректный код ответа/ошибка на уровне
> самого API теперь тоже считается багом, даже если фронтенд с ним справляется. Пункт про
> `500 вместо 404/400` по этой причине **перенесён из этого раздела в таблицу багов выше**
> как [BUG-005](./BUG-005-categories-endpoint-wrong-error-status.md).

- **`promotions` — JSON-массив на одних страницах и JSON-объект на других** (на стороне API `www.mechta.kz`, страница 2 списка акций). Технически контракт нарушен, но фронтенд одинаково корректно отрисовывает обе формы (проверено визуально) — пользователь ничего не замечает. Задокументировано в `api_promotions.cy.js` как тест на контракт (падает на уровне API-теста, но не является user-facing багом).
- **Зависание при связке `category=<валидная>&type=<валидный, но 0 пересечений>`** (например `posuda-i-aksessuary` + `gift`) — при первой попытке наблюдалось то же зависание, что в BUG-001, но при повторных проверках на чистых вкладках страница стабильно самокорректировалась (сбрасывала `type` и показывала список по одной категории). Не смог надёжно воспроизвести — не оформлено отдельным багом, но стоит понаблюдать: возможна редкая гонка состояний при клиентской навигации.
- **Выбор вида акции сбрасывает ранее применённую сортировку** (категория при этом сохраняется). Подтверждено на реальном сайте, изначально фиксировалось как баг — по уточнению это ожидаемое поведение продукта, не дефект. Зафиксировано как обычный тест поведения (не баг) в `catalog_combinations.cy.js` → `COMBO-001`.
