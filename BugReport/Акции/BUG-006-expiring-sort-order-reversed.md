# BUG-006: Сортировка «Скоро закончатся» (`sortBy=expiring`) выдаёт акции в обратном порядке

**Раздел:** Акции — каталог акций (`/useful/shares/`), сортировка списка
**Severity:** Medium
**Приоритет:** Medium
**Статус:** Подтверждён (UI + прямой `curl` по всем 3 страницам ответа)
**Дата обнаружения:** 2026-08-07

## Окружение

- UI: `https://pp.yc.mechta.kz/useful/shares/?sortBy=expiring` (вкладка «Скоро закончатся 🔴»)
- API: `GET https://www.mechta.kz/api/v3/promotions?sortBy=expiring&page={1,2,3}`
- Заголовки: `Accept: application/json`, `X-City-Code: astana`
- Сегодняшняя дата на момент проверки: 2026-08-07

## Предусловия

Пользователь находится в разделе «Акции» (`/useful/shares/`), список акций содержит акции с разными сроками истечения (проверено на живых 21 акции).

## Шаги воспроизведения

1. Перейти на `/useful/shares/`.
2. Кликнуть вкладку сортировки **«Скоро закончатся»** (значок 🔴 рядом с названием явно обещает семантику «скоро истекают»).
3. Посмотреть на первую карточку списка / сравнить порядок карточек по датам «по ... г.».

Либо напрямую через API:
```bash
curl -s "https://www.mechta.kz/api/v3/promotions?sortBy=expiring&page=1" \
  -H "Accept: application/json" -H "X-City-Code: astana" \
  | jq '.promotions[] | {slug, toDate, daysBeforeExpiration}'
```

## Ожидаемый результат

Вкладка «Скоро закончатся» должна показывать акции в порядке **возрастания** `daysBeforeExpiration` (по возрастанию `toDate`) — то есть акция, которая истекает раньше всех, должна быть первой в списке.

## Фактический результат

Список отсортирован **строго по убыванию** `daysBeforeExpiration` — акции с самым дальним сроком истечения показаны первыми, а акция, которая истекает быстрее всех, оказывается на **последней (3-й) странице**.

Полный порядок `daysBeforeExpiration` по всем трём страницам ответа `sortBy=expiring` (проверено 2026-08-07, сегодня = 2026-08-07):

```
Стр.1: 146, 146, 146, 146, 146, 146, 146, 86, 44, 30
Стр.2: 29, 24, 24, 24, 24, 24, 23, 13, 9, 3
Стр.3: 2
```

Акция `umnye-naushniki-s-ii-chipom` (истекает через **2 дня** — `toDate: 2026-08-09`) — самая близкая к истечению из всех 21 — оказывается на 3-й странице списка, а акции с `toDate: 2026-12-31` (146 дней в запасе) показаны первыми на 1-й странице.

Первая карточка на вкладке «Скоро закончатся» в UI: **«При покупке кофемашины – скидка -50% на три пачки зернового кофе!»**, срок «с 3 марта 2026 г. по **31 декабря 2026 г.**» — то есть акция с одним из самых дальних сроков истечения из всех 21, а не с ближайшим.

## Почему это баг

Порядок сортировки прямо противоречит собственной семантике, заявленной лейблом вкладки и красным индикатором-предупреждением «🔴 Скоро закончатся» (оракул Claims/User expectations) — цель этого сортировщика по назначению (Purpose) — помочь пользователю быстро найти акции, которые вот-вот пропадут, а на практике он показывает противоположное: акции, которые точно ещё долго провисят. Это дефект на уровне самого API (`GET /api/v3/promotions?sortBy=expiring` отдаёт неверно упорядоченный список) — фронтенд лишь корректно отображает то, что получил, поэтому проблема не во фронтенд-обработке, а в направлении сортировки на backend.

## Вероятная причина

Похоже, что при сортировке `ORDER BY days_before_expiration` (или эквивалентное поле даты истечения) перепутано направление — используется `DESC` вместо ожидаемого `ASC` (по возрастанию срока, оставшегося до истечения).

## Автотест, фиксирующий баг

`cypress/e2e/regress_test/promotions_regress.cy.js` → `REGR-PROMO-004` — тест на сортировку `sortBy=expiring` целенаправленно ожидает, что `daysBeforeExpiration` каждого следующего элемента `<=` предыдущего (по возрастанию срочности), и падает, пока баг не исправлен.
